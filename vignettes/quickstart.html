motiongrammar Quickstart

motiongrammar processes human tracking data — GPS, RFID, optical — through a reproducible pipeline:

initiate → coordinate → interpolate → filtrate → derivate
         → designate → elaborate → allocate → quantitate

This guide loads a real GPS export, builds a reusable template, then runs it through every step.

0. Setup

devtools::load_all("..")
require(tidyverse)

path <- file.path("..", "data", "marquee_gps_file.csv")

1. Guess — let motiongrammar figure out the file

initiate(source = "guess_csv") sniffs the column layout automatically. It handles preamble rows, fuzzy column names, and timestamp formats.

2. Inspect the detected template

guess_csv only imports the four core columns (time, lat, lng, altitude). guess_csv_template() shows exactly what was detected so you can extend it:

tmpl <- guess_csv_template(path)
tmpl
#> CSV Template [gps]
#>   skip: 6  |  max_empty_lines: 3  |  comment: '#'  |  duplicate_method: return_error
#>   Column mapping:
#>     unix_time <- UnixTimestamp
#>     lat          <- Latitude
#>     lng          <- Longitude
#>     altitude     <- Elevation

Add the device-specific extra columns, then save the template — once saved, anyone on the team can import this device format consistently, without guessing:

tmpl <- csv_template(
  col_unix     = "UnixTimestamp",
  col_lat      = "Latitude",
  col_lng      = "Longitude",
  col_altitude = "Elevation",
  col_extra    = c("HeartRate", "PlayerLoad", "MetabolicPower", "Cadence"),
  skip         = 6L
)

template_path <- tempfile(fileext = ".xml")
save_csv_template(tmpl, template_path)

Reload at any time (from another script, a different machine, years later):

tmpl <- load_csv_template(template_path)

tr <- initiate(session = path, template = tmpl, verbose = FALSE)

HeartRate, PlayerLoad, MetabolicPower, and Cadence are now columns that will carry through every downstream step.

4. Coordinate — project to metres

GPS coordinates are spherical (degrees). coordinate() projects them to a flat Cartesian plane so distances, velocities, and headings are in metres. norm = TRUE places the first position at the origin.

tr <- coordinate(tr, norm = TRUE)
ggplot(tr, aes(x, y)) +
  geom_path(alpha = 0.6, linewidth = 0.4) +
  coord_fixed() +
  labs(title = "Projected trajectory (before interpolation)",
       x = "x (m)", y = "y (m)") +
  theme_minimal() +
  theme(panel.grid = element_blank())

5. Interpolate — regularise the frame rate

GPS signals drop out. interpolate() builds a regular 10 Hz time grid and fills short gaps linearly. Gaps longer than max_gap_frames rows are left as NA rather than invented — preserving the 14-second gap flagged earlier.

tr <- interpolate(tr, hz = 10, method = "linear", max_gap_frames = 20)

6. Filtrate — smooth the coordinates

Find the cutoff

filtrate_cutoff() sweeps a range of Butterworth cutoffs and plots the residual curve. The elbow marks where smoothing starts removing real signal rather than noise.

filtrate_cutoff(
  tr,
  method       = "butterworth",
  target       = "coordinates",
  axis         = "x",
  plot_type    = "both",
  cutoff_range = c(0.1, 4),
  n_steps      = 40
)

A cutoff of ~1–2 Hz is typical for GPS position data at 10 Hz. The dashed red line is the suggested value — adjust based on the PSD panel.

Apply the filter

filtrate() stores the smoothed signal in f_x, f_y columns and leaves the originals untouched. derivate() will use the filtered columns by default.

tr <- filtrate(tr, method = "butterworth", target = "coordinates", cutoff = 1.5)
drop_na(tr, f_x) |>
  ggplot(aes(x = unix_time)) +
  geom_line(aes(y = x,   colour = "Raw"),      linewidth = 0.3) +
  geom_line(aes(y = f_x, colour = "Filtered"), linewidth = 0.5) +
  scale_colour_manual(values = c(Raw = "firebrick2", Filtered = "dodgerblue")) +
  labs(title = "x coordinate: raw vs filtered",
       x = "Unix time (s)", y = "x (m)", colour = NULL) +
  theme_minimal() +
  theme(panel.grid = element_blank())

7. Derivate — velocity, acceleration, angular velocity

derivate() computes derivatives using central differences. It uses the filtered f_x, f_y columns by default.

tr <- derivate(
  tr,
  use_filtered = TRUE,
  derivatives  = c("velocity", "acceleration", "angular_velocity")
)

Angular velocity captures whether the player is running straight or turning — a continuous signal more nuanced than a discrete “change of direction” event:

drop_na(tr, angular_velocity) |>
  ggplot(aes(f_x, f_y, colour = angular_velocity)) +
  geom_path(linewidth = 1) +
  coord_fixed() +
  scale_colour_viridis_c(option = "viridis", begin = 0.1, end = 0.9) +
  labs(title = "Angular velocity mapped onto trajectory",
       x = "x (m)", y = "y (m)", colour = "deg/s") +
  theme_minimal() +
  theme(panel.grid = element_blank())

8. Designate — identify activity bouts

designate() uses PELT changepoint detection on the velocity signal to split the session into contiguous active bouts and relief periods — no manual timestamps required.

tr <- designate(tr, method = "corbett", v_threshold = 0.3)
ggplot(tr, aes(unix_time, velocity, colour = designation)) +
  geom_line(linewidth = 0.4) +
  labs(title = "Velocity coloured by designated segment",
       x = "Time (s)", y = "Velocity (m/s)", colour = NULL) +
  theme_minimal() +
  theme(panel.grid = element_blank(),
        legend.position = "bottom")

9. Elaborate — add custom metrics

elaborate() is a motion_trace-safe dplyr::mutate() wrapper. It preserves the metadata and quality attributes that a bare mutate() would silently drop. Use it to add computed columns or fix derived values before profiling:

tr <- elaborate(
  tr,
  curved_load = velocity * abs(angular_velocity),  # direction-weighted load
  velocity    = pmin(velocity, 8)                  # cap GPS teleport spike
)

10. Allocate — assign intensity bands

allocate() cuts any derivative into labelled bands. Call it multiple times with different allocation_name values to layer profiling schemes on the same trace without conflict:

tr <- allocate(
  tr,
  allocation = list(
    velocity     = c(0, 2, 4, 6, 8),
    acceleration = c(0, 1, 2, 3)
  ),
  allocation_name = "gps_bands"
)

11. Quantitate — summarise

quantitate() aggregates by designation segment and intensity band. The full quality log is preserved as an attribute on the result.

By segment and velocity band:

by_segment <- quantitate(
  tr,
  allocation  = "gps_bands",
  derivative  = "velocity",
  scope       = "designation",
  active_only = TRUE,
  time_s      = n() / 10,
  peak_vel    = max(velocity, na.rm = TRUE),
  mean_hr     = mean(HeartRate, na.rm = TRUE)
)

Saving results

write_csv drops R attributes. Use saveRDS to keep the full object:

saveRDS(tr, "session_processed.rds")

readr::write_csv(by_segment, "by_segment.csv")

saveRDS(attr(tr, "quality"), "quality_log.rds")

Pipeline at a glance

tr <- initiate(session = path,
               template = load_csv_template("my_device.xml"),
               verbose  = FALSE) |>
  coordinate(norm = TRUE) |>
  interpolate(hz = 10, max_gap_frames = 20) |>
  filtrate(method = "butterworth", target = "coordinates", cutoff = 1.5) |>
  derivate(use_filtered = TRUE,
           derivatives  = c("velocity", "acceleration", "angular_velocity")) |>
  designate(method = "corbett", v_threshold = 0.3) |>
  elaborate(curved_load = velocity * abs(angular_velocity),
            velocity    = pmin(velocity, 8)) |>
  allocate(allocation      = list(velocity = c(0, 2, 4, 6, 8)),
           allocation_name = "gps_bands")
